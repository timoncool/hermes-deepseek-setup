# Первая настройка Hermes с DeepSeek

## Проверка подключения

- Работай на том профиле и шлюзе, которые пользователь собирается применять. По интерфейсу, статусу сеанса или безопасному чтению конфигурации проверь провайдера и модель. Для старта предложи прямой DeepSeek и `deepseek-flash`. Если модель уже отвечает и подходит пользователю, оставь её.
- Если активен другой провайдер, сохрани рабочее подключение. Покажи, как в Hermes Desktop открыть «Настройки → Провайдеры → API-ключи → DeepSeek», вставить ключ и нажать «Сохранить», затем открыть «Модель → Основная модель», выбрать DeepSeek и нужную модель и нажать «Применить». Для активного сеанса модель меняется рядом с полем ввода.
- Если API ещё не настроен, дай пользователю ссылки на [пополнение](https://platform.deepseek.com/top_up) и [создание ключа](https://platform.deepseek.com/api_keys). Оплату и ввод ключа он выполняет сам. Не запрашивай ключ, реквизиты карты или содержимое файлов с секретами. При ошибке доступа предложи проверить баланс в кабинете, прямого провайдера и сохранение ключа, затем повторить короткий запрос вручную. Если текущая модель не отвечает, эти действия нужно выполнить до вызова скилла.

## Настройка под задачи

1. Спроси одним сообщением, что пользователь хочет поручать Hermes, в каких приложениях и папках работает и есть ли у него инструкции от другого агента. Начни с одной реальной задачи. Покажи, как выбрать для неё рабочую папку, и согласуй, что можно читать и менять. Для первого изменения файлов предложи отдельную тестовую папку или копию.
2. Покажи короткий план настройки с тем, что уже работает. Сначала проверь доступные инструменты, скиллы, плагины и MCP-подключения. Для каждого нового компонента назови его точный источник, нужный доступ и пользу для названной задачи. После согласия установи только выбранные компоненты по документации установленной версии Hermes. Не записывай секреты в чат, логи или инструкции.
3. При переезде попроси указать конкретный проект и файлы правил, которые пользователь хочет перенести. Вначале открой их для чтения. Предложи точечный перенос применимых правил в существующий проектный `AGENTS.md` или другой явно выбранный файл. Сохрани существующие правила и покажи предлагаемые изменения перед записью.
4. Выполни согласованную пробу и покажи наблюдаемый результат. Для файлов это может быть итоговый файл и его путь, для MCP — вызов безопасной команды состояния. Если пользователь выбирает Speech Studio, попроси открыть программу на компьютере, где работает Hermes. Прочитай раздел [For AI agents](https://github.com/timoncool/speech-studio#for-ai-agents), подключи локальный сервер по инструкции после согласия и проверь `studio_status`. При удалённом шлюзе объясни, что `127.0.0.1` указывает на машину шлюза.
5. В конце дай короткую памятку для этого пользователя. Укажи, как открыть новую сессию в нужной папке, какие инструменты доступны, какой результат проверен и один следующий запрос на его реальную задачу. Отметь любой ручной шаг, который ещё ждёт пользователя.

## Проверка изменений

Перед проверкой новой сессии уточни, нужно ли переключить модель по умолчанию для всего профиля или только для текущей задачи. После установки скилла или подключения инструмента проверь, что он появился в установленной версии, и при необходимости открой новую сессию. Сообщай об успехе после наблюдаемой проверки. Сбой одного дополнения не мешает провести пробную задачу доступными инструментами.

## Подбор и установка расширений

Веди настройку на русском и по одному решению за раз. Сначала спроси, какую работу человек хочет закончить сегодня, а затем уточни привычные приложения, рабочую папку и уровень опыта. Если человек отвечает «не знаю», предложи одну пробу из его собственной сферы и начни с неё. Объясняй команды и результаты обычным языком.

- На нужном компьютере и профиле проверь `hermes skills list`, `hermes plugins list` и доступные MCP-подключения. Внутри чата можно использовать `skills_list`. Для дополнительного профиля проверь синтаксис `hermes -p <профиль> …` через справку. Если терминал привязан к другой машине, оставь настройки на нужном шлюзе и покажи, как открыть правильный терминал.
- По каждой реальной задаче найди актуальные инструкции производителя инструмента, документацию Hermes и страницы подходящих дополнений. Используй `hermes skills search <задача>`, `hermes skills inspect <идентификатор>`, `hermes plugins search <задача>` и `hermes mcp catalog`. Запросы формулируй по задаче без частных имён, путей и файлов. Предпочитай встроенное, официальный каталог и репозиторий разработчика. Сверь поддержку ОС, требования к аккаунтам и доступу, дату обновления. Дай ссылки и предложи небольшой набор для первой задачи.
- После выбора пользователя установи компоненты сам. Скилл — `hermes skills install <точный идентификатор>`. Плагин из каталога — `hermes plugins install <имя>`, затем проверь статус и при необходимости включи его командой `hermes plugins enable <имя>`. MCP из каталога — `hermes mcp install <имя>`. Для документированного HTTP-сервера используй `hermes mcp add <имя> --url <адрес>`, если эти флаги поддерживает установленная версия. Для Speech Studio локальный адрес из README — `http://127.0.0.1:8797/mcp`. Сохраняй исходные настройки и не перезаписывай существующее подключение с тем же именем без согласия. Если установщик запросил отдельное разрешение или логин, помоги пройти именно этот шаг.
- Для переноса полного набора настроек из Claude Code или Codex найди официальный плагин `agent-importers`. После согласия установи его из каталога и сначала запусти `hermes import-agent claude-code --dry-run` или `hermes import-agent codex --dry-run`. По плану выбери с человеком только нужное. Если штатный импорт захватывает больше, перенеси отдельно выбранные правила или скиллы. Полный перенос секретов и разрешений не входит в обычную первичную настройку.
- После каждого изменения проверь, появился ли компонент в списке, а затем вызови один доступный инструмент или выполни небольшую задачу. Если нужно, обнови список скиллов или открой новый сеанс. В итоговой памятке дай конкретные команды, готовые примеры запросов и один способ отключить каждое новое расширение. Оставь текущую сессию пригодной для продолжения работы.
