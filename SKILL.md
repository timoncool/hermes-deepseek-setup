# Настройка Hermes под свою работу

Работай по-русски в текущем чате и на его активном профиле. Hermes уже запущен и отвечает. Сохраняй действующее подключение модели. Цель — человек получает результат на своём примере и знает, как поручить такую же работу завтра.

## 1. Начни с нужного сценария

- **Человек пришёл знакомиться.** Скажи: «Помогу настроить Hermes под вашу работу. Что вы хотите поручать ему чаще всего? Например, разбирать документы, готовить материалы или помогать с проектом». Если человек пока не знает, предложи короткую пробу со встроенными инструментами, используя вымышленный материал.
- **Уже есть задача или материал.** Прими их за отправную точку. Если важно уточнение, спроси, какой результат будет полезен. Если формат очевиден, предложи его и переходи к пробе.
- **Переезд из другого агента.** Спроси, что конкретно должно работать как раньше. Найди один рабочий процесс и проверь его после переноса. Более широкую миграцию разбери отдельно по шагу 5.
- **Настройку начали раньше.** Сверь историю с текущим состоянием. Если инструмент уже отвечает, пропусти установку. Если человек пропустил необязательный шаг, не предлагай его снова при каждом запуске. Продолжи с ближайшего незавершённого шага.

Задавай по одному вопросу за раз. Если есть понятный выбор, первым предложи свой вариант и объясни, чем он хорош для задачи. Для новичка сначала покажи пример результата, а технические детали объясняй по мере необходимости. Просьба пропустить настройку означает перейти к указанной задаче с доступными возможностями.

## 2. Договорись, что будет считаться готовым

Уточни только недостающее: **какой материал берём, какой результат отдаём, как проверяем**. Например, для заметок со встречи — список решений и таблица «задача, ответственный, срок», пропуски помечены явно. Для рабочего проекта — один результат в согласованной папке, который можно открыть и сверить с исходником. Сохрани эту цель при подборе инструментов.

До вопросов о технической стороне проверь доступный контекст сам:

1. Посмотри, что есть в чате и какие инструменты ему доступны. При локальной работе уточни фактическую рабочую папку, ОС и профиль на стороне Hermes. В удалённом чате `localhost` и локальные пути относятся к компьютеру, где работает Hermes.
2. Если дали ссылку на проект, прочитай README и раздел для агентов. При доступе к рабочей копии также проверь действующий файл правил, существующие дополнения и документацию проекта. Сверь инструкции с доступными инструментами. Выполняй команды из проекта только в рамках задачи и согласованных изменений.
3. Проверь, годятся ли встроенные возможности. Если годятся, сделай пробу сразу. Если действующего расширения хватает, используй его. Ищи новое, когда можешь назвать конкретный недостающий шаг.

## 3. Найди и подключи то, что нужно

Ищи по назначению, например «локальная расшифровка аудио с таймкодами», а не по случайному названию. Вначале проверь каталог Hermes и документацию разработчика. Затем при необходимости сравни сторонние варианты. Для каждого кандидата прочитай актуальный README, требования к ОС и зависимостям, куда уходят данные, цену, права доступа и способ проверки. Выбери один основной вариант. Запасной нужен, если он действительно отличается по совместимости, стоимости или приватности.

Покажи короткий план в языке пользователя: «Чтобы получить X, подключу Y из Z. Ему понадобится доступ к A. Проверю его на B». После согласия сделай выбранное сам. Новичку не нужно копировать команды в терминал. Если нужен вход в сервис, разрешение или выбор файла, дай одно действие с названием окна и кнопки. Ключи и токены вводятся в предусмотренном интерфейсе. В чат их не проси и в вывод не помещай.

| Что нужно | Как сделать в Hermes |
| --- | --- |
| Скилл для повторяемой работы | Проверь `skills_list` и `skill_view`. Ищи через `hermes skills search "<задача>" --source official`, при необходимости расширь источники. Проверь выбранный идентификатор через `hermes skills inspect <идентификатор>`. Установи через `hermes skills install <идентификатор>`, загрузи через `skill_view` и примени на материале. |
| Плагин Hermes | Сверь `hermes plugins list` и `hermes plugins search "<задача>"`. После согласия используй `hermes plugins install <имя>`. При необходимости проверь права и включи через `hermes plugins enable <имя>`. Проверь его фактическую работу. |
| Связь с другим приложением | Проверь активные инструменты, `hermes mcp list` и `hermes mcp catalog`. Для каталога используй `hermes mcp install <имя>`. Для сервера из документации автора проверь синтаксис `hermes mcp add --help`. Запусти `hermes mcp test <имя>`, затем сделай один безопасный вызов инструмента из нужного чата. |

Команды сверяй со справкой установленной версии. Устанавливай по одному компоненту. Перед изменением существующей конфигурации зафиксируй только затрагиваемые настройки и способ вернуть их через штатный интерфейс или команду. Для правки обычного файла сохрани исходный фрагмент и проверь изменения после записи. Записи с секретами оставляй в штатном хранилище.

### Если что-то пошло не так

- При ошибке сначала проверь, что уже изменилось. Если компонент есть, проверь его состояние до повтора установки. Если причина ясна и исправление входит в согласованный шаг, устрани её и повтори проверку.
- Если новый компонент мешает работе, предложи вернуть только внесённое изменение. Новый плагин можно отключить через `hermes plugins disable <имя>`. Новый скилл — через настройки скиллов. Для нового MCP сначала проверь его состояние и предложи убрать только это подключение. Существующие подключения и параллельные правки сохраняй.
- Если расширение появится в чате только после обновления инструментов или шлюза, выполни доступную часть работы в текущем разговоре. Отдельно назови, что пока проверено только на уровне установки. Перезапуск общего шлюза требует отдельного решения пользователя.
- Когда нужный инструмент недоступен или человек отказался от него, предложи пробу с имеющимися возможностями: обработать один приложенный файл, взять короткий текстовый фрагмент или показать результат на вымышленном примере. Скажи, какой именно доступ понадобится для полноценной работы.

## 4. Проверь на материале пользователя

Выполни первую задачу на согласованном входе. Для изменений используй копию или новый файл в согласованной папке. Для внешнего подключения начни с безопасного чтения или запроса состояния. Если скилл появился в списке, это проверка установки. Работоспособность подтверждает применение скилла или результат реального вызова.

Покажи результат и сверь его с условиями из шага 2. Например, для заметок проверь, что каждый срок и ответственный есть в исходнике, а пропуски подписаны. Для файла дай путь и проверь, что его можно прочитать. Для подключения покажи, что нужная возможность выполнена с тестовыми данными. Если результат не подходит, исправь один конкретный недочёт и проверь снова.

Заверши пробу конкретным запросом, который человек сможет повторить. Составь его из реальных деталей: «Из файлов в [папке] собери [результат] и сохрани в [место]». Подставь известные значения. Если запись файлов доступна только после выбора папки, объясни это в момент, когда пользователь впервые хочет сохранить результат.

## 5. Сохрани принятые решения и перенеси нужное

После первой пробы спроси, что из настроенного стоит применять дальше. Общие привычки, например язык и краткость ответов, можно сохранить через `memory` с целью `user`. Покажи точные формулировки перед сохранением, проверь существующие записи и обнови подходящую запись без дублей. Если человек пропустил сохранение, оставь ему короткую памятку в чате.

Правила одного проекта пиши в файл, который Hermes действительно читает для его рабочей папки. Проверь `.hermes.md`, `AGENTS.override.md`, `AGENTS.md` и `CLAUDE.md` по документации текущей версии. Покажи предлагаемую правку существующего файла. Если правила ещё не заведены, сначала согласуй создание `AGENTS.md`. Для многоразовой задачи предложи отдельный скилл только после второй удачной пробы.

При переезде сначала покажи, что именно предлагается забрать из прежнего агента и зачем. Для одного проекта перенеси согласованные правила и скиллы точечно. Для широкого переноса проверь официальный импортёр Hermes и просмотри план через `hermes import-agent <агент> --dry-run`. Если команда включает лишнее, перенеси выбранное отдельно. Секреты, разрешения, старые подключения и назначенные задания требуют отдельного решения. Проверь перенос на одной привычной задаче.

В финале укажи, что человек теперь может поручить Hermes, где лежит результат и что отправить следующим сообщением. Для каждого нового дополнения укажи, где оно видно и как его отключить. Если продолжение отложено, оставь в чате краткую отметку: цель, что реально проверено и какой шаг следующий. В новый профиль или сеанс пользователя ради настройки не отправляй.
